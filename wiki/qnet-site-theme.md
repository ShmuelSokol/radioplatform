# The qnet look on every staff page (`.qn-site`)

Shmuel (2026-11-17): "design the rest of the site to look more like qnet", his name for the station's old program (KBR Studio 1.82). The control room and the Databank already had it (`.qn`, [control-room](control-room.md)). Every other admin page and the sponsor portal now get it from one shared skin instead of page by page rewrites. Listener pages (`/stations`, `/listen`, `/guide`, `/hosts`, `/archives`, `/call`) keep their own look.

## How it works

- `Layout.tsx` puts `qn-site` on the page wrapper for `/admin/*` (`isQnetPage`), `Navbar.tsx` puts it on the menu bar for the same paths, `SponsorLayout.tsx` always has it. The control room and Databank are app shells: only their menu bar gets `qn-site`, their panes keep `.qn`.
- `src/styles/qnet-site.css` (hand written) restyles by element and by Tailwind class: grey window face, `h1` as a navy title bar, any `bg-white` or navy card as a raised panel, anything button-like that carries a `bg-*` class as a raised grey button, text boxes sunken white, `select` grey with the raised arrow, tables as a sunken white list with grey column buttons, square corners, no soft shadows.
- `src/styles/qnet-site-colors.css` is GENERATED by `scripts/gen-qnet-colors.mjs`. It reads every colour class the pages use and writes one rule per class (`.qn-site [class~="text-cyan-300"]{color:#000080}`): light text meant for the old dark pages becomes dark, dark navy panels become the grey face, dark tints become light tints, grey lines become bevel grey. `npm run build` regenerates it and `npm run lint` fails if the committed file is stale, so a new colour class on a page is picked up.

## Writing a page

Write ordinary Tailwind; the skin does the rest. Things worth knowing:

- A coloured button (`bg-blue-600` etc.) becomes grey; a blue/green/etc. one is drawn as the default button (bold, black frame). Pages mark the chosen tab or filter by colouring it, so that frame is also what "selected" looks like. `aria-pressed/selected/checked="true"` draws pressed. Red buttons keep a red label.
- `rounded-full` things (dots, pills, switches, round record buttons) are left alone. `qn-plain` on a button or link opts it out of the button face.
- Phones (coarse pointer, under 768 px): every button, select and box is 44 x 44 px, and so is the label of a checkbox or radio button (the label is the tap target). A box with no words beside it is wrapped in `<label className="qn-tap">` (Library rows). The control room sets its own sizes (`h-11 lg:h-6`). The floating bug button is hidden on the Library at phone size, where rows have controls on both edges; it is in the menu there.
- White text survives only on a strong colour (500 to 800 shade) set on the same element or its parent badge; elsewhere `text-white` becomes black.
- `[class~=...]` matches whole class names, so `hover:bg-x` never triggers the `bg-x` rule. Only plain and `hover:` colour classes are remapped; `md:`/`focus:` colour variants are not.
- Specificity is `.qn-site` + one attribute (0,2,0), above Tailwind utilities, with no `!important`. Inline styles still win.
- Do not change page markup for the look; fix it in the skin. Layout rules stay in [admin-page-layout](admin-page-layout.md).

## Checking it

`e2e/admin-layout-audit.mjs` (sideways scroll at 1920, 390 and 320 px) and `e2e/admin-flows.mjs` both run against the skinned pages. Look at screenshots too (`SHOTS_DIR`); the checks do not catch ugly. The first pass found two 320 px overflows caused by the wider bold buttons and select arrows (Schedules card header now wraps; `select` and `label` may shrink).
